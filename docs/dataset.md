# Dataset reference

What the three raw FitRec files contain. Every number is in
[results/dataset_stats.json](../results/dataset_stats.json), regenerated by
`python src/00_document_dataset.py`. Openable extracts are in [samples/](../samples/).

---

## The three files nest strictly

```
endomondoHR_proper  ⊂  endomondoHR  ⊂  endomondoMeta
     167,783              253,020          962,190
```

Verified on workout `id` — not a single record falls outside the nesting.

| | Meta | HR | HR_proper |
|---|---|---|---|
| Size | 9.89 GB | 6.12 GB | 4.59 GB |
| Records | 962,190 | 253,020 | 167,783 |
| Running records | 347,558 | **117,902** | 70,591 |
| Distinct running users | 1,234 | **865** | 807 |
| GPS coordinates | **no** | yes | yes |
| Heart rate | no | yes | yes |

Meta holds every workout; the HR files hold only those where a heart-rate monitor was worn
(26% of all workouts); `_proper` narrows that again to densely-sampled ones.

All three are **line-delimited Python dict reprs** — single quotes, `None`, not JSON. Parse
with `ast.literal_eval`, never `json.loads`. Where only scalars are needed, a regex per field
is far faster than parsing.

## `endomondoHR.json` — the file this work uses

**10 or 11 fields; the schema is not uniform.**

| Field | Always | Type | Unit |
|---|---|---|---|
| `id`, `userId` | yes | int | — |
| `sport`, `gender`, `url` | yes | str | — |
| `latitude`, `longitude` | yes | list[float] | degrees |
| `altitude` | yes | list[float] | metres |
| `heart_rate` | yes | list[int] | bpm |
| `timestamp` | yes | list[int] | Unix seconds |
| `speed` | **18.8%** | list[float] | **km/h** |

**Array lengths are not fixed.** Only ~70% reach 500; lengths as short as 9 occur, and `speed`
can differ in length from the rest within one record.

Gender, running records: 107,882 male (91.5%), 9,360 female (7.9%), 660 unknown.

49 sports. Top: run 117,902 · bike 98,001 · mountain bike 13,510 · bike (transport) 10,445 ·
walk 3,831 · indoor cycling 2,606.

## `endomondoHR_proper.json`

**Identical schema** to the above — there is nothing to merge between the two files, contrary
to an early assumption that one held heart rate and the other coordinates.

What the filter keeps is **sampling density, not heart-rate quality**: every array in `_proper`
is exactly 500 elements long without exception, where in the parent only ~70% are.

| | Kept | Excluded |
|---|---|---|
| Distinct timestamps | median 500, min 494 | median 345, min **1** |
| Duration | median 64.1 min | median 27.2 min, min 0.0 |
| Degenerate heart rate | 0% | 2% |

Not used here: the "≥500 genuine points" rule exists for the original paper's heart-rate
sequence task. Route work does not need it, and inheriting it would discard ~47,000 usable
runs. Kept as a control set.

## `endomondoMeta.json` — summaries, no coordinates

13 fields, uniform schema. ~13 KB of each 14 KB record is the ISO timestamp array; dropping it
turns 9.89 GB into ~70 MB.

Scalar fields: `distance` (km), `duration` (s), `calories`, `ascent`, `descent`, `hydration`,
`weather`.

**Completeness, running records:** distance 100.0% · duration 100.0% · calories 99.6% ·
ascent/descent 95.4% · weather 70.5% · hydration 16.4%.

Distance and duration being complete is what makes junk filtering possible without touching a
single GPS array.

**`weather` has two shapes.** Of the 244,888 running records that have it, 74% are a bare
`{'type': N}` and 26% also carry `temperature`, `humidity`, `wind_speed`, `wind_direction`. So
real weather context exists for about **18% of running workouts** — a candidate RQ2 feature.
`type` itself is an undocumented code, values 1–43.

**Value ranges, running records:** distance median 7.73 km (max 2,364); duration median
43.4 min (min **−229**, max 715,881). The extremes are real data — negative durations and
497-day workouts exist and must be filtered.

## Known defects

**`speed` is usually absent** — 18.8% of running records. Use `rec.get("speed")`.

**`speed` is km/h, not mph.** The published FitRec schema says mph. Integrating each record's
own GPS track and comparing gives a median ratio of 1.02 against km/h; mph would give 0.62.

**HR and Meta timestamps disagree** by 7 or 8 hours for the same workout — +7 h March–November,
+8 h November–February, November the only overlapping month, so it is daylight saving. Harmless
for ordering; **fatal for any time-of-day analysis.**

**Sport labels are raw**, including the typo `stair climing`.

**Padded recordings exist** — distinct timestamp counts as low as 1.

All three of the first claims are reproduced by `python src/01_verify_dataset.py`.
